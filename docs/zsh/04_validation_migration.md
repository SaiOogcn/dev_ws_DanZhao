# 实车迁移、标定、回归和验收

[返回总说明](../../README.md)

目标是把定位、地图、规划、控制和底盘组成可解释、可复现的闭环。文档完成不等于实车验收通过；本次未新增实车测试结论。

## 1. 分阶段实现顺序

| 阶段 | 实际工作 | 交付与进入下一阶段的条件 |
| --- | --- | --- |
| P0：接口和标定 | 确认传感器、时钟、TF、轮速、轴距和控制协议 | 静止/低速采集记录，坐标与单位一致，唯一命令来源 |
| P1：建图 | 选择 NdtLIO 模式或现有二维 NDT-EKF，完成去畸变和质量诊断 | 可重复路线地图，残差与退化有日志，不能只截一张地图 |
| P2：地图与定位 | 保存定位地图，重启载入，初始匹配、滤波初始化和失效门控 | 从已知场地位置恢复并稳定定位；错误地图和错误初值被拒绝 |
| P3：算法移植 | 将定位适配、障碍处理、局部规划、MPC 与 ROS 接口接入独立包 | 离线日志回放可重复，明确节点入口与安装规则，尚不发底盘命令 |
| P4：执行器辨识 | 测量转向增益、滞后、阻尼、延迟和制动能力 | 参数有来源及有效速度范围，模型能解释实测响应 |
| P5：低速闭环 | 直线、定圆、单锥桶、双锥桶、窄通道、倒车停车 | 位置和姿态跟踪稳定，车头车尾均无碰撞，故障停车有效 |
| P6：完整任务 | A/B/C 各段、顺逆时针、多个锥桶、返回停车 | 每段切换正确，路线连续，未发生控制权冲突 |
| P7：速度优化 | 根据算力、制动距离、曲率和定位质量逐步提高速度 | 多次重复成功，并记录最差情况；不以最快单次代替稳定性 |

每个阶段保留代码版本、参数版本、地图版本、实车尺寸、ROS 包版本和日志。禁止以“节点启动成功”替代后续阶段。

## 2. 建议的代码落地位置

算法已经整理到独立的 [src/zsh_navigation](../../src/zsh_navigation/README.md)，包含 ROS 2 安装规则、入口、参数和测试。它与小车既有 `zsh_pkg` 分开，不覆盖任何已有包；下面是实际模块分层，详细文件链接见 [源码索引](05_source_index.md)。

```text
src/zsh_navigation/
  定位适配层          # 明确 map/odom/body、时间和有效状态
  场地与任务层        # 路线、方向、边界、阶段切换
  障碍物层            # 去畸变、聚类、时序记忆、轮廓
  局部规划层          # Frenet、航向格点、解析连接
  车辆模型与 MPC 层   # 实车标定、约束、CEM 求解
  ROS 接入层          # 唯一控制权、底盘单位、超时诊断
  config/             # 本车参数，不覆盖他人默认值
  launch/             # navigation.launch.py；默认预览模式
```

该包采用 `ament_python`，安装 `full_race_navigation` 和 `audit_course` 两个入口。源码和离线检查已交付，仍需用户在小车本机选择包构建后验证安装结果。定位核心继续由独立定位包提供。

新增 MPC 时替换基线控制输出或通过单一仲裁器接入；定位器可以独立对照，两个运动控制器不能同时直连底盘。回退版本应有独立参数和明确启动入口，便于恢复既有基线。

## 3. 参数标定顺序

| 类别 | 必须获取的量 | 错误后的常见表现 |
| --- | --- | --- |
| 几何 | 轴距、车宽、前后悬、车体到后轴/雷达/IMU 变换 | 轨迹看似通过，轮胎或车尾碰桶 |
| 时间 | 扫描起止定义、IMU 延迟、轮速延迟、系统时钟偏差 | 转弯地图重影，障碍随车移动 |
| 定位 | IMU 零偏与噪声、匹配尺度、点数、质量阈值 | 漂移、跳变、滤波过度自信 |
| 转向 | 指令单位、正负号、增益、死区、速率、延迟与响应 | 前轮抖动，转弯半径不符，控制饱和 |
| 驱动/制动 | 目标速度到实际速度响应、减速度和看门狗行为 | 来不及停车，换挡冲击 |
| 障碍 | 激光高度、锥桶底座尺寸、观测误差和记忆时长 | 蹭底座、虚障碍、遮挡后漏检 |
| 规划/控制 | 时域、采样预算、曲率与速度限制、代价权重 | 求解超时、绕行犹豫、过度减速 |

先纠正几何、时间和协议，再调权重。否则控制器可能通过偏置参数暂时掩盖错误，在换方向或倒车时再次失效。

## 4. 可重复的验收用例

- **定位**：静止、直线往返、左右转弯、闭合路线、重启载入、错误初值、短时遮挡与恢复。记录相对独立参考的误差；没有独立参考时仅能报告一致性与漂移，不能宣称绝对厘米级精度。
- **控制**：不同速度的直线、定圆、曲率连续与不连续路径、倒车、前后换挡和终点停车。检查角速度/转角单位、实际响应和饱和比例。
- **避障**：单桶、左右交错多桶、C 区内外侧桶、入口桶、窄缝、出口汇合点桶、桶底座擦边及车尾扫掠。保存锥桶布置坐标和实物尺寸。
- **不可行场景**：完全封堵通道、两侧均无足够车宽、起点被障碍包围。成功行为是明确减速/停车与原因报告，不是强行完赛。
- **故障**：扫描过期、定位中断、时间倒退、错误 frame、地图版本错误、后台规划延迟、控制器退出、推理服务超时。确认旧轨迹和旧命令不会持续驱动车辆。
- **任务**：重复识码不重复切段，拍照重试不重复执行任务，方向选择正确，返程不跳到出发路线，最终实际速度归零。

故障注入先在日志回放和不接驱动输出的模式验证；接实车时需现场控制条件。正常多锥桶通行不应频繁触发倒车脱困，但无法安全前进时允许进入明确的恢复状态。

## 5. 需要记录的指标

| 指标 | 计算建议 |
| --- | --- |
| 完赛时间 | 统一起终点事件，同时报告任务等待和实际行驶时间 |
| 成功率 | 固定场景重复多次，给出总次数、成功次数和失败原因 |
| 跟踪误差 | 横向、航向误差的中位数、P95 与最大值，分前进/倒车 |
| 最小净空 | 真实全车轮廓到锥桶底座/墙的距离，明确测量方法 |
| 转向平顺性 | 指令与实际/估计轮角、转角速率、饱和时间、振荡次数 |
| 停顿 | 次数、时长和触发原因，区分任务停车与避障犹豫 |
| 实时性 | 控制耗时 P50/P95/P99、超时率、规划耗时和结果年龄 |
| 定位质量 | 匹配残差、有效点、修正幅度、位姿年龄、重定位成功率 |
| 安全边界 | 碰撞、越界、失控、故障停车和剩余停止距离 |

比较原 Pure Pursuit 和新 MPC 时使用相同场地、障碍布置、最大允许速度、车辆参数和成功判定。区分“提高速度上限带来的时间变化”和“控制方法本身减少停顿的收益”。记录最差试次，不能仅展示最好一次。

## 6. 常见现象到排查路径

| 现象 | 优先检查 |
| --- | --- |
| 前轮一直抖 | 命令来源 → Twist/转角单位 → 位姿跳变 → 路径切线 → 转向动态模型 |
| C 区绕障僵硬 | 是否仅看最近桶 → 参考点与车尾 → 连续偏移与汇合 → 换侧滞回 → 计算超时 |
| 一加速就漏桶 | 停止距离与总延迟 → 感知年龄 → 扫掠采样间隔 → 预测时域 |
| 雷达有频率但无定位 | QoS → frame → 时间 → 模式订阅 → 初始化 → 有效点与退化 |
| 有地图但控制没位姿 | Odometry 是否真的发布 → frame 是否填写 → TF 是否在独立话题 → 重定位门控 |
| 保存地图后重启失败 | 只保存了栅格还是定位地图 → 地图加载路径 → 初值与滤波初始化 |
| 路线突然跳段 | 最近点全局搜索 → 环道分支混淆 → 缺少赛段/弧长窗口 → 定位重置 |
| 两个节点都在线但车不走 | 是否等待释放或实际静止 → 是否仍在键盘启动前 → 当前控制权与拒绝原因 |

## 7. 当前尚不能宣称完成的部分

本分支已有二维定位与 Pure Pursuit 源码，并新增 `zsh_navigation` 导航、避障、CEM-MPC、真实 ROS 适配和安装入口。尚未完成的是本车执行器辨识、现场接口/坐标核验和闭环验收；独立 NdtLIO 的地图持久化/重载、全局重定位质量门控和各模式统一 Odometry 仍须补齐。源码交付不等于这些实车环节已经验收。

本次不提供仿真完赛数字，不承诺 20 秒实车完赛或无条件不停。完成这些接入与验收后，才能把方法说明升级为“当前版本实测能力”。源码对应关系见 [索引](05_source_index.md)。
