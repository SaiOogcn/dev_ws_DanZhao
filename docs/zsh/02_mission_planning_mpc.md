# 任务、路径规划、多锥桶避障与 CEM-MPC

[返回总说明](../../README.md)

本文分开说明仓库现有基线和目标算法。现有代码入口是 [pure_pursuit_node.cpp](../../src/origincar/lio_hybird/src/pure_pursuit_node.cpp)；后文 CEM-MPC 及其模块拆分是实车移植方法，本次没有添加相应算法源码或新节点。

## 1. 路线和任务状态机

每个赛段使用同一场地坐标，保存参考路径、允许区域、方向 `gear`、速度上限、目标航向、切段条件及任务触发器。建议路径点至少表达 `x, y, yaw, s, curvature, target_speed, gear, stage_id`；这是目标数据契约，不是已有路径 TXT 的固定格式，读取旧路径时需适配。

| 方法中的赛段 | 主要行为 | 退出条件 |
| --- | --- | --- |
| `OUTBOUND_A` | A 区出发，建立稳定跟踪 | 到达接近段且姿态匹配 |
| `TASK_AREA_APPROACH` | 接近任务区，预留拍照/识码点 | 进入任务窗口，必要任务确认 |
| `REVERSE_TRANSFER_A` | 刹停换挡，沿倒车路线转移 | 实际位置、航向和尾部通过条件满足 |
| `ENTER_B_CHANNEL` | 对齐 B 区通道，约束全车宽度 | 整车进入通道 |
| `ENTER_C_RING` | 提前处理 C 区入口锥桶 | 稳定汇入环道 |
| `C_RING_CW / C_RING_CCW` | 按任务方向绕行并连续避障 | 到达规定出口窗口 |
| `EXIT_C_RING` | 保持出口曲率连续，检查尾部 | 整车退出环道 |
| `EXIT_B_CHANNEL` | 沿返回通道行驶 | 通道和车尾全部通过 |
| `RETURN_A_AND_PARK` | 返回 A 区，末段降速并停车 | 位置、航向、实际速度同时满足 |

不能只凭最近路径点编号切段。环道相邻路线很近，最近点搜索应限制在前向弧长窗口，结合当前赛段和进度，避免跳到对向或另一条支路。定位重置后重新建立进度，禁止沿用旧段索引。

换挡流程为“制动 → 验证实测速度接近零 → 切换方向 → 跟踪新路径”。倒车时路径前进方向、车体航向和速度符号要分别定义，不能简单将前进控制角取负。

二维码、拍照、显示和大模型任务使用独立任务状态，不在高频控制回调中同步等待网络。重复识码应去重，同一拍照任务使用唯一任务编号。外部服务超时后按比赛规则选择重试或报告失败；导航能否继续由任务规则决定，不能假装推理已完成。

## 2. 本仓库现有避障基线

当前 `pure_pursuit_node` 使用 Pure Pursuit 跟踪，结合空间 S 形候选轨迹、障碍记忆和制动/倒车脱困逻辑。历史说明提到的 TEB 已不是当前控制实现，也不能仅凭包名 `lio_hybird` 推断它使用 Hybrid A*。

现有实现包括扫描聚类与二次确认、墙体/外围过滤、有限时长的障碍记忆、全车矩形检查、路线前向重捕获。相关参数应以 [lio_hybird.yaml](../../src/origincar/lio_hybird/config/lio_hybird.yaml) 和源码为准。

现有主动避障场景中某些禁行区域采用软代价，不能将其描述为任何情况下都严格不可穿越。实车比赛应按规则明确哪些边界是硬约束，再与新的局部规划器保持一致。

脱困不是日常绕障策略。基线有制动、选择倒车轨迹、倒车、稳定和重规划等阶段，并限制尝试次数；目标方案优先通过提前规划和连续速度避免频繁进入这些状态。

## 3. 多锥桶感知链

1. 按扫描时间和位姿历史，将观测变到统一场地坐标；过期扫描不能套用最新位姿后当作实时障碍。
2. 对相邻束或空间邻近点聚类，做有效点数、距离和尺寸检查；在连续观测中确认目标，抑制单帧杂点。
3. 定位仍保留墙体；控制侧单独识别墙段和外围背景，避免将墙过滤逻辑误用到建图链。
4. 利用已标定激光高度和锥桶尺寸拟合锥身，仅在置信度足够时还原更宽的底座。否则保留原始点及保守包络。
5. 维护带时间戳的短期障碍记忆，并按观测可见性清除；不能永久保留旧锥桶，也不能遮挡一帧就立即删除。
6. 规划障碍快照同时保留多个目标和场地约束，检查整段路径，而非只对最近一个点计算转向斥力。

膨胀量覆盖观测误差、定位误差和车体尺寸不确定性，随速度适度增加。若已经用整车多边形碰撞检测，需清楚区分测量裕量与车辆半宽，避免重复膨胀到通道全部不可行。

## 4. 双层局部规划

### 4.1 连续路线：Frenet 侧向绕障

将局部候选写成参考曲线的侧向偏移：

```text
p(s) = r(s) + d(s) n(s)
d(s) = a0 + a1 s + a2 s² + a3 s³ + a4 s⁴ + a5 s⁵
```

用起点与终点的侧向位置、一阶和二阶导数约束求解六个系数。起点导数应依据实际车体航向与参考切向关系确定，不能只匹配位置而让候选从车头横向折出去。保留真实车辆航向，用后轴参考点构建几何关系。

在多个偏移量、绕行长度与汇合位置上生成候选。检查起始过渡、所有前方锥桶、全车轮廓、曲率上限和重新并回的原路线。若只检查绕开第一个锥桶的一小段，后续仍可能撞第二个锥桶。

代价包含路线偏差、曲率与曲率变化、通行余量、路径长度和跨周期换侧代价。上一周期的绕行侧仍可行时保持连续性；该侧失效则允许切换，不能把“保持侧别”做成无法退出的锁。

### 4.2 狭窄连接与倒车：航向格点搜索

搜索状态包含 `(x, y, yaw, gear)`，用满足最小转弯半径的车辆运动原语扩展；在近目标区域尝试 Hermite 等解析连接，但连接结果仍需验证曲率、行驶方向、整车扫掠和边界。

终点不只是一个位置：包含目标车体朝向、方向以及必要的末段直线。倒车目标要根据后轴或车体参考点正确换算；车尾与保险杠也参与碰撞检查。

规划器设置计算预算和失败返回。搜索超时不是“前方可通行”，应保留仍有效旧路径或进入安全降速流程。

### 4.3 后台规划与轨迹版本

耗时搜索放到独立进程或其他不阻塞控制的执行单元。Python CPU 密集搜索不能仅靠普通线程就假定消除了 GIL 影响。提前准备倒车和返回段，但所有结果都携带赛段、地图、障碍和定位版本。

新路线返回时，检查起点是否已被车辆越过、新障碍是否使其失效、与当前航向是否能连续连接。只有重新验证通过才切换；不接受过期结果，不在等待搜索期间临时做与规划方向相反的绕行。

## 5. 车辆与转向响应模型

内部控制定义为纵向速度 `v` 和前轮等效转角 `δ`，轴距为 `L`。以后轴为参考的运动学模型：

```text
x_dot = v cos(θ)
y_dot = v sin(θ)
θ_dot = v tan(δ) / L
```

若定位参考点在后轴前方距离 `b` 处，则该点速度还包含转动项：

```text
ω = v q / L,  q 为实际等效 tan(δ)
x_dot = v cos(θ) - b ω sin(θ)
y_dot = v sin(θ) + b ω cos(θ)
θ_dot = ω
```

`b` 依据 TF 和尺寸标定，不默认等于半轴距。不能用车体中心轨迹预测后轴，却拿后轴碰撞框判断车头。

转向系统存在响应时间、阻尼、增益和可能的纯延迟。可用二阶状态描述：

```text
z = [q, q_dot]ᵀ
z_dot = A z + B q_target
A = [[0, 1], [-ωn², -2ζωn]]
B = [0, ωn²]ᵀ
q_target = K tan(δ_cmd)
Ad = exp(A dt), Bd = integral(exp(A τ) B, τ=0..dt)
```

使用离散模型预测实际轮角，并在需要时加入延迟命令队列。`K`、`ωn`、`ζ` 和延迟需要实车辨识。没有轮角传感器时可由速度与实测角速度估计等效响应，但要剔除低速除零、打滑和定位跳变区间，不能将模型估计值称为实测轮角。

## 6. CEM-MPC 求解方法

这里的 CEM 是交叉熵采样优化，不等同于 Nav2 MPPI。几何跟踪控制和曲率前馈提供基础动作，优化其上的低维转向修正与速度比例，减少搜索维数。

可作为初始计算配置：控制周期 `0.05 s`，预测步长 `0.06 s`，预测 24 步约 `1.44 s`；用 3 个转向修正节点和 3 个速度比例节点插值生成动作序列，每轮采样 48 个候选、迭代 2 轮。这些是方法起点，尚未证明适合本车算力和最高速度，必须通过真实耗时分位数与超时率调整。

```text
读取位姿、实际速度、估计转向状态、当前任务和障碍快照
检查时间戳、坐标、定位质量和控制权
将上一周期解向前移，构建几何引导序列
重复有限轮 CEM：
    采样低维参数，插值得到速度与转向序列
    在每一步预测中施加转角速率、加速度和速度约束
    推进转向模型和车辆模型
    检查整车扫掠、障碍、边界和末端可制动条件
    对可行候选计算代价，利用精英样本更新分布
选择可行解，只执行第一步，保存热启动状态
无可行解时执行经过检查的制动策略并报告原因
```

典型代价：

```text
J = Σ (wy*ey² + wψ*eψ² + wv*(v-vref)²
       + wδ*δ² + wΔδ*(Δδ)² - ws*progress)
    + terminal_cost + clearance_penalty
```

碰撞和禁止越界应先判不可行，不能仅给有限大惩罚后仍允许被“更大进度收益”抵消。离散预测间还要检查扫掠，采样间距随速度和障碍尺度设置，避免跳过窄障碍。

## 7. 提速同时保持可控

弯道速度上限由横向加速度约束：`v_curve ≤ sqrt(a_lat_max / max(|κ|, ε))`。沿路线向后传播制动约束：`v_i² ≤ v_(i+1)² + 2 a_brake Δs`，在进入弯道之前减速。

可用停止距离必须覆盖 `D_stop = v τ + v²/(2 a_brake) + margin`，其中 `τ` 包括扫描、定位、计算、通讯和执行延迟。若没有可靠速度反馈或制动标定，就没有依据保证提高速度后仍能避开锥桶。

前轮抖动排查顺序：

1. 排除多个节点争发命令、角速度与转角混用、前后轴参考点错误。
2. 检查扫描时间和定位跳变，避免把定位抖动当转向控制误差。
3. 检查路径切线、曲率和切段连续性，加入合理换侧滞回。
4. 让转向限速和执行延迟进入预测，再调整转向变化代价和控制频率。
5. 使用实测指令到响应时序辨识模型；不能只在输出端加重低通滤波，造成预测外的更大滞后。

目标是减少不必要的停车和过度刹车。定位失效、通道被堵、无可行轨迹时仍必须停车；20 秒左右完赛只能作为经过安全约束后的优化目标，不能作为删除这些约束的理由。

## 8. 控制权、失败和实车接口

为控制器设计 `WAIT_LOCALIZATION → READY → TRACKING → BRAKING → RECOVERING / FAULT → FINISHED` 等运行状态。等待地图、定位过期、搜索超时、无可行轨迹和任务失败分别给出原因，避免都显示“卡住”。

现有视觉控制与路径控制使用释放确认交接。新 MPC 可以替换原路径控制器，或者向私有候选话题发送命令，由唯一仲裁器输出 `/cmd_vel`；后者为建议接口，仓库当前并没有因此自动具备命令仲裁节点。

最终指令通过 [接口文档](03_interfaces_bringup.md) 规定的单位和启动路径进入底盘，验证方法见 [迁移与验收](04_validation_migration.md)。
