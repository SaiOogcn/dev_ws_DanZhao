## 三、整体系统方案

本车以 RDK X5 为主控，采用“视觉感知 + 激光/惯性融合定位 + 分阶段运动控制 + 车端/本地电脑协同推理”的总体方案。系统按照赛事四项子任务组织运行：

1. **自主前往任务发布点：** 前置摄像头获取赛道和障碍物信息，`origincar_control` 根据视觉检测结果完成巡线、转向和动态避障，使车辆自主到达任务发布区域。
2. **任务信息获取与展示：** 前置摄像头图像由 `zxing_qr_code_detection` 完成二维码检测与解码；二维码数字及由其确定的顺、逆时针方向通过 `qr_screen_display` 显示。车辆在任务发布区采用倒车姿态/倒车机动，使车尾 Aurora 930 对准图文标记牌并完成图像采集。
3. **黄色通道任务：** 扫码成功并停车后，系统将底盘控制权由视觉巡线模块切换给 `lio_hybird`。车辆根据二维码结果选择顺时针或逆时针预设路线，结合实时定位与局部避障完成黄色通道内的自主行驶及任务动作。
4. **自主返回停车点：** `lio_hybird` 继续进行路径跟踪和避障，引导车辆返回 P 点，并在终点区域完成停车。

整体流程如下：

`启动与IMU静态校准 → 前视巡线/避障 → 二维码识别与方向判定 → 停车并切换控制器 → 倒车取景与图生文 → 按指定方向通过黄色通道 → 返回P点 → 屏幕显示任务结果`

## 四、技术方案概述

### 1. 视觉巡线、避障与扫码

前置摄像头承担第一赛段的主要环境感知任务。`origincar_control` 接收视觉检测结果，依据赛道线位置计算转向控制量，并利用障碍物目标的位置和尺度选择绕行方向。二维码识别采用基于 ZXing-C++ 的 `zxing_qr_code_detection`，识别结果发布到 ROS 2 通信网络；系统按照二维码信息确定后续通道的顺、逆时针行驶方向。

### 2. 多传感器融合定位与路径跟踪

`base_orin` 负责底盘通信、轮速里程计和 IMU 数据发布，并在启动静止阶段进行陀螺仪零偏校准。`lio_hybird` 融合 IMU 角速度、轮速信息和 N10 激光雷达二维扫描数据：由 IMU/轮速进行运动预测和扫描去畸变，通过关键帧 NDT 子地图匹配修正车辆在场地坐标系中的位姿；随后采用纯追踪控制器跟踪预设路径，同时依据雷达障碍点、车体边界和场地约束进行局部避障。该方案可支持前进、倒车及换向路径，并在扫码后按任务方向切换对应路线。

### 3. 图像采集与大模型图生文

在图文信息采集阶段，路径控制程序在设定位置触发拍照。车尾 Aurora 930 获取最新图像后，图像客户端对画面进行方向校正、缩放和 JPEG 编码，并通过与 `rdk_client_test_0.4.py` 一致的 ZMQ 通信协议发送至本地电脑。本地电脑加载视觉大模型完成图像内容识别和中文描述生成，再将文字结果返回车辆。网络通信和推理在独立工作线程中进行，不阻塞车辆的定位与运动控制。

### 4. 信息显示与系统协同

`qr_screen_display` 统一订阅二维码内容、行驶方向和图生文结果，在车载屏幕上显示四位二维码数字、顺/逆时针方向及中文图片描述。各功能模块通过 ROS 2 话题解耦；扫码后采用“先制动、确认视觉控制释放、再由定位导航控制器接管”的方式切换底盘控制权，避免多个控制程序同时输出速度指令。
