## 📋 常用报告与文档提交指南

本队伍使用 GitLab Issue 来管理各类报告和会议纪要。请在对应时间节点，选择正确的模板创建 Issue，并按模板要求填写。

| 报告类型 | 模板文件 | 提交频率 | 责任人 |
|----------|----------|----------|--------|
| **个人阶段反馈报告** | `个人阶段反馈报告.md` | 每1周一次 | 每位队员 |
| **个人赛后总结报告** | `个人赛后总结报告.md` | 比赛结束后一周内 | 每位队员 |
| **团队阶段技术报告** | `团队阶段技术报告.md` | 每4周一次 | 队长/指定负责人 |
| **团队赛后总结报告** | `团队赛后总结报告.md` | 比赛结束后两周内 | 队长/指定负责人 |
| **内部会议纪要** | `内部会议纪要记录.md` | 每次例会后 | 记录人 |

> **提示**：创建 Issue 时，右侧 **“Choose a template”** 下拉菜单中选择对应模板即可自动填充。

## 🧾 采购与报销流程

如需购买实验材料或设备，请严格按照以下流程操作，确保报销顺利。

### 1. 提交采购申请
- 使用模板 **`备赛材料采购申请.md`** 创建 Issue。
- 下载并填写 [《实验材料采购申请单》Excel 模板](https://git.tongji.edu.cn/tjsrclab/common-resources/lab-templates/-/blob/main/templates-fund/TJSRCL模板=附件F0：实验材料采购申请单_内部使用_xxxx竞赛_2026新版.xlsx)，上传至 Issue。
- 标签会自动设为 `类型::采购` 和 `状态（采购）::待审批`，指派给指导教师。

### 2. 后续状态流转
请参照 **[采购报销流程指南](https://git.tongji.edu.cn/tjsrclab/common-resources/lab-templates/-/blob/main/templates-fund/ReadMe.md)** 中的详细说明，跟踪你的申请状态。

## 🏷️ 标签体系说明

为了便于分类和跟踪，本项目使用了从根群组继承的标签体系。所有标签已按作用域分组，在 Issue 侧边栏中清晰可见。

| 作用域 | 标签示例 | 说明 |
|--------|----------|------|
| 类型 | `类型::采购`、`类型::报告`、`类型::会议纪要` | 区分不同事务 |
| 状态（采购） | `状态（采购）::待审批`、`状态（采购）::已批准`、`状态（采购）::采购中`、`状态（采购）::待验收`、`状态（采购）::报销中`、`状态（采购）::需整改`、`状态（采购）::已完成` | 采购流程各阶段 |
| 状态（报告） | `状态（报告）::待提交`、`状态（报告）::进行中`、`状态（报告）::待审核`、`状态（报告）::已完成` | 报告流程各阶段 |
| 优先级 | `优先级::高`、`优先级::中`、`优先级::低` | 紧急程度 |

## 🤝 团队协作守则

1. **代码管理**：所有代码请提交至 `src/` 目录，重要更新请创建合并请求并指派审核。
2. **报告提交**：按时通过 Issue 提交，逾期会影响团队进度。
3. **采购申请**：必须提前提交 Issue 审批，**未经审批的采购无法报销**。
4. **沟通留痕**：所有技术讨论、问题反馈请在对应 Issue 或合并请求中评论，避免使用私聊（方便追溯）。
