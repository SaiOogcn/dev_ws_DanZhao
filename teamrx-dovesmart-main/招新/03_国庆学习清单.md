# 国庆学习清单（10/1 ~ 10/8）

> 给新队员的话：这份清单不要求你「学会机器人」，只要求你**把环境搭起来、
> 把概念混个脸熟、并且真的动手让什么东西跑起来**。
> 八天下来你只要做到「能在自己的电脑上跑起 ROS 2、能看懂我们的一段代码」就够了，
> 剩下的进来一起做。
>
> 给负责人的话：所有链接都已核实可用（B 站播放量是核对时的数据）。
> 难度按 **A 线（零基础，必做）** 和 **B 线（有基础，选做）** 分开，
> 新生只需要走完 A 线。

## 怎么用这份清单

1. **不要只看视频**。每天必须有一个「动手做出来的东西」，哪怕只是让终端打印一行字。
2. **每天写三行小结**：今天学了什么、卡在哪里、怎么解决的。八天后交一份《学习小结》。
3. **卡住超过 1 小时就问群里**，不要卡一整天。但问之前先把报错原文贴出来，
   并说明你已经试过什么。
4. **不要追求看完**。视频看不完很正常，挑重点；看完了什么都没做才是白看。

## 前置准备（10/1 之前或当天上午完成）

- 一台能装双系统 / 虚拟机的电脑（**推荐直接装 Ubuntu 22.04 双系统**，
  虚拟机在后面的图像和 RViz 环节会很吃力）；
- 或者 Windows 用户可先用 **WSL2 + Ubuntu 22.04** 起步（后面做图形界面会受限）；
- 一个 GitHub 账号；
- 手机装好 B 站，把这几个 UP 主关注了：**古月居GYH、鱼香ROS机器人、DR_CAN**。

> 我们有现成的机器人，所以**这次不用买任何硬件**，
> 你要练的是「软件怎么跑起来」这件事。

## Day 2（10/2）：ROS 2 是什么

**看**

- 【古月居】古月·ROS2 入门 21 讲（约 111 万播放）：
  <https://www.bilibili.com/video/BV16B4y1Q7jQ>
  —— **优先看前 10 讲**，后面可以留到假期结束慢慢补。
- 官方文档（英/中文可切换）：<https://docs.ros.org/en/humble/Tutorials.html>

**做**（这是整个假期最重要的一次动手）

```bash
# 安装 ROS 2 Humble（Ubuntu 22.04），或者用一键安装工具：
# https://github.com/fishros/install  （★3200，国内网络友好）

# 安装后，开两个终端：
ros2 run demo_nodes_cpp talker      # 终端 1
ros2 run demo_nodes_py listener     # 终端 2

# 再开一个终端观察：
ros2 node list
ros2 topic list
ros2 topic echo /chatter
ros2 topic hz /chatter
```

**必须搞懂的五个词**：节点（node）、话题（topic）、消息（message）、
参数（parameter）、launch 文件。

**加分**：跑一下小海龟 `ros2 run turtlesim turtlesim_node`，
再开 `ros2 run turtlesim turtle_teleop_key` 用键盘控制它。

**交**：截图 `ros2 topic list` 的输出，并解释 `/chatter` 和 `/rosout` 分别是什么。

## Day 4（10/4）：图像处理入门（OpenCV）

**看**

- 【唐宇迪】基于 Python 与 OpenCV 的图像处理（约 122 万播放）：
  <https://www.bilibili.com/video/BV14A411C7ZE>
  —— 只看**图像读取显示、颜色空间转换、阈值分割、形态学、轮廓**这几节就够了。

**做**（这三件事正好对应我们代码里做的事）

1. 读一张图片，转成 HSV，用滑动条（`cv2.createTrackbar`）调出黄色的阈值范围；
2. 对二值图做开运算/闭运算，观察噪点变化；
3. 找出所有连通域，按面积过滤掉太小的。

**对照我们的代码读**：
`src/origincar/image_binary/src/image_binary.cpp`

你会发现里面的 HSV 区间、开闭运算核大小、最小面积，就是你今天调的那几个参数。
（提醒：那个文件里 `GREEN_` 开头的宏其实存的是黄色阈值，`YELLOW_` 开头的存的是绿色，
当年命名起反了，注释是对的。）

**交**：一张「原图 + 二值图」的对比截图，说明你用的阈值范围。

## Day 5（10/5）：控制入门 —— 让一个点沿着路走

**看**

- 【小黎的Ally】路径规划与轨迹跟踪系列 · 第 10 讲 纯跟踪法（约 4 万播放）：
  <https://www.bilibili.com/video/BV1Ly4y177dF>

**做**（用 Python + matplotlib，不需要任何硬件）

1. 随便生成一条曲线（比如一段圆弧或正弦线）当作「路径」；
2. 写一个虚拟小车，从起点出发，每次找前方固定距离的点当**前瞻点**，
   算出应该往哪转、往前走多远；
3. 把它画成动画，观察：前瞻距离调大一点、调小一点，轨迹有什么变化。

**对照我们的代码读**：
`src/guandao/src/guandao_node.cpp`（只有 444 行，是全项目里最适合入门的一个控制器），
以及它的说明 `src/guandao/README.md`。它做的事情和你今天写的几乎一样：
读位姿 → 找前瞻点 → 算速度 → 发布。

**顺带认识两个词**

- **阿克曼转向**：前轮转向的车，转弯时左右轮角度不一样，所以不能像坦克一样原地转；
- **PID**：一种「根据误差大小来决定修正力度」的控制方法。你只要理解
  「比例项看现在、积分项看过去、微分项看趋势」就够了，不用会推导。

**交**：一段 10 秒左右的动画录屏，或者三张不同前瞻距离下的轨迹对比图。

## Day 6（10/6）：定位入门 —— 为什么需要「融合」

**看**

- 【DR_CAN】卡尔曼滤波器系列（约 56 万播放）：
  <https://www.bilibili.com/video/BV1ez4y1X7eR>
  —— **只要求看前 2~3 集**，理解「用不确定的预测 + 不确定的观测，
  得到更确定的估计」这个思想。公式推导看不懂可以直接跳过。
- （备选，更偏应用）【华南小虎队】卡尔曼滤波从理论到实践（约 81 万播放）：
  <https://www.bilibili.com/video/BV1Rh41117MT>

**要理解的三个问题**（比记公式重要）

1. 如果只有轮子转了多少圈，车的位置会不会越算越偏？为什么？
2. 如果只有激光雷达，能不能知道自己在哪？
3. 两个都不太准的东西加在一起，为什么反而更准？

**对照我们的代码读**：
`src/origincar/lio_hybird/README.md` 里的「数据流」那一段，
看我们是怎么用轮速和 IMU 做**预测**、用激光雷达做**修正**的。
再打开 `config/ekf.yaml`，找到这几行并按注释理解它们的意思：

```yaml
frequency: 20.0        # 输出频率
two_d_mode: true       # 只在平面上估计，因为我们只在地面跑
odom0: /odom           # 输入 1：轮速里程计
imu0: /imu/data        # 输入 2：IMU
```

**交**：用三句话回答上面那三个问题（不许抄百科，用你自己的话）。

## 附三：验收与常见坑

### 假期结束时我们怎么验收

| 检查项 | 合格标准 |
| --- | --- |
| 环境 | 能在自己的电脑上跑起 `talker` / `listener`，会 `ros2 topic echo` |
| 动手 | 至少有 3 天留下了截图或链接证据（Python 脚本、二值图、纯追踪动画…） |
| 代码 | 能用自己的话讲清一个包在干什么 |
| 小结 | 交了，而且第 3 条「最没搞懂的概念」写得具体 |

> 我们**不查你看了多少视频**，只查你跑起来了什么、卡住时怎么处理的。

### 常见坑（提前告诉你，能省很多时间）

1. **Ubuntu 版本要对上**：ROS 2 Humble 对应 Ubuntu 22.04。
   装成 20.04 或 24.04 会一路报错。
2. **装完 ROS 要 `source`**：每次开新终端都要
   `source /opt/ros/humble/setup.bash`，否则会提示「找不到 ros2 命令」。
   可以把它写进 `~/.bashrc` 一劳永逸。
3. **虚拟机跑不动图形程序**：RViz、摄像头预览在虚拟机里会非常卡，
   有条件就装双系统。
4. **`grep` 报错先看是不是路径写错了**，不要急着怀疑命令本身。
5. **卡住时先问自己三个问题**：
   我的输入对不对？我跑的是不是我刚改的版本？报错的第一行说了什么？
   —— 这三个问题能解决我们队 80% 的 bug。
6. **不要一天装三样东西**。一次只折腾一个环境，装完立刻验证，
   不然出问题时你根本不知道是哪一步引入的。
